# Planner — راهنمای ساخت، نصب و تست

شناسه‌ی برنامه: `ir.dehgmahdi.planner` · حداقل اندروید ۶ (API 23) · Target API 36 · خروجی: APK امضاشده با کلید دائمی

## ۱) آپلود پروژه به GitHub
1. فایل zip را باز کن. باید پوشه‌ی `planner-android` را ببینی.
2. **محتویات** همین پوشه را (نه خود پوشه را) تو ریشه‌ی ریپازیتوری بریز: `app/`، `.github/`، `build.gradle.kts`، `settings.gradle.kts`، `gradle.properties`، `icon.png`، `README.md`. در صفحه‌ی ریپازیتوری روی Add file ← Upload files بزن و همه را بکش. پوشه‌ی مخفی `.github` هم باید بیاید.
3. فایل‌های قدیمی (`main.dart`، `planner.html` در ریشه و workflow قدیمی) را حذف کن.

## ۲) ساخت کلید امضای دائمی (یک بار، روی ویندوز)
بدون این کلید، ساخت عمداً متوقف می‌شود تا هیچ APK با کلید موقت ساخته نشود.
1. PowerShell را باز کن و این را بزن (مسیر Android Studio را اگر فرق دارد عوض کن):
```
& "C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" -genkeypair -v -keystore planner.jks -alias planner -keyalg RSA -keysize 2048 -validity 10000
```
رمز را دو بار بنویس و اسم و اطلاعات را پر کن. فایل `planner.jks` ساخته می‌شود.
2. **از `planner.jks` و رمزش چند نسخه‌ی پشتیبان بگیر** (فلش، ایمیل خودت). اگر گم شود، دیگر هیچ آپدیتی روی برنامه‌ی نصب‌شده ممکن نیست. هیچ‌وقت آن را تو GitHub آپلود نکن.
3. کلید را به متن تبدیل کن: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("planner.jks")) | Set-Clipboard`
4. تو GitHub: Settings ← Secrets and variables ← Actions ← New repository secret. این چهار تا را بساز:
   - `KEYSTORE_BASE64` (متن مرحله‌ی ۳)
   - `KEYSTORE_PASSWORD` (رمز فایل)
   - `KEY_ALIAS` (`planner`)
   - `KEY_PASSWORD` (معمولاً همان رمز)

## ۳) ساخت و دانلود
تب Actions ← Build Planner APK ← Run workflow. بعد از حدود ۵ تا ۱۰ دقیقه، تو صفحه‌ی همان اجرا، پایین (Artifacts) فایل `Planner-apk` را بگیر. داخل zip فایل `Planner-1.0.N.apk` است. شماره‌ی نسخه (Version Code) با هر ساخت خودکار بالا می‌رود. گزارش اجرا، اثر انگشت گواهی امضا را هم نشان می‌دهد؛ تو همه‌ی ساخت‌ها باید یکسان باشد.
اگر قرمز شد: روی مرحله‌ی قرمز بزن و خطوط بعد از `What went wrong` را بفرست.

## ۴) نصب و انتقال اطلاعات
- شناسه‌ی جدید است، پس **کنار** برنامه‌ی قدیمی نصب می‌شود و چیزی حذف نمی‌شود.
- از این نسخه به بعد هر APK جدید مستقیم روی قبلی نصب می‌شود و اطلاعات می‌ماند.
- انتقال از نسخه‌ی قدیمی: اگر پشتیبانی که از برنامه‌ی قدیمی گرفتی (فایل یا متن JSON) داری، تو برنامه‌ی جدید تنظیمات ← بازیابی از فایل را بزن. فرمت‌های قدیمی (کارها، عادت‌ها) خوانده و تبدیل می‌شوند و عادت‌های قدیمی «کار روزانه» می‌شوند. اگر فقط متن داری، آن را تو یک فایل با پسوند `.json` ذخیره کن.

## ۵) چک‌لیست تست روی گوشی (فقط روی گوشی ممکن است)
۱. نصب روی گوشی، باز شدن بدون خطا، آیکن درست.
۲. تنظیمات ← فعال‌سازی اعلان ← اجازه بده ← «اعلان آزمایشی» می‌آید.
۳. یک کار با ساعت ۲ دقیقه‌ی بعد بساز (یادآوری «سر وقت»)، برنامه را کامل ببند (از لیست برنامه‌ها حذفش کن): اعلان سر وقت بیاید.
۴. دکمه‌ی «۱۰ دقیقه بعد» روی اعلان: ۱۰ دقیقه بعد دوباره بیاید.
۵. گوشی را ریستارت کن (برای کاری که ساعتش هنوز نرسیده): بعد از روشن شدن یادآور هنوز بیاید.
۶. ویجت: صفحه‌ی اصلی را نگه دار ← Widgets ← Planner. کارهای امروز دیده شوند؛ تیک زدن کار را خط‌خورده کند؛ «+» برنامه را با فرم کار جدید باز کند؛ زدن روی عنوان همان کار را باز کند. بعد از باز کردن برنامه، کار تیک‌خورده تو برنامه هم انجام‌شده باشد.
۷. تنظیمات ← تهیه نسخه‌ی پشتیبان ← ذخیره تو Download؛ بعد بازیابی از همان فایل.
۸. تنظیمات ← انتخاب پوشه (مثلاً Documents/Planner) ← پشتیبان خودکار روشن. یک فایل `planner-auto-...json` با «همین الان» نمی‌سازد؛ نسخه‌ی خودکار هفتگی توسط اندروید اجرا می‌شود و ممکن است با محدودیت باتری دیر شود. تاریخ آخرین پشتیبان موفق تو تنظیمات نوشته می‌شود.
۹. باتری برنامه را «بدون محدودیت» کن (به‌خصوص شیائومی، سامسونگ، هوآوی) تا اعلان و پشتیبان‌گیری قطع نشوند.
۱۰. یک APK با شماره‌ی بالاتر بساز و روی نسخه‌ی قبلی نصب کن: بدون حذف، کارها بمانند.

## ۶) تصمیم‌ها و محدودیت‌ها (گزارش صادقانه)
- **فناوری:** پوسته‌ی Flutter با Kotlin بومی جایگزین شد (حجم کمتر، اعلان دقیق و ویجت و WorkManager مستقیم). رابط HTML حفظ شد.
- **تست‌شده:** منطق و رابط (کارهای روزانه/هفتگی/ماهانه، بدون تاریخ، قفل روزهای گذشته، توقف عادت، زمان واقعی، آمار، بازیابی و مهاجرت از فرمت‌های قدیمی) با تست خودکار در Node اجرا شدند.
- **تست‌نشده:** کدهای Kotlin اینجا کامپایل نشدند و روی گوشی هم اجرا نشدند. اعلان واقعی، ویجت، پشتیبان خودکار و ساخت در GitHub Actions باید با چک‌لیست بالا بررسی شوند. اولین ساخت ممکن است یک خطای کوچک بدهد.
- **رنگ مقایسه‌ی زمان:** تا ۲۰٪ اختلاف سبز، تا ۴۰٪ زرد، بیشتر قرمز (ثابت `ACC` بالای اسکریپت `planner.html`).
- **پنجره‌ی زمان واقعی** فقط برای کارهایی باز می‌شود که مدت تخمینی (برای عادت‌ها: هدف زمانی) دارند. تیک زدن از ویجت پنجره‌ی زمان را باز نمی‌کند.
- **هفتگی/ماهانه:** یک بار در هفته (شنبه تا جمعه، قابل تغییر در تنظیمات) یا ماه شمسی. تاریخ اختیاری است؛ با تاریخ، کار تو صفحه‌ی همان روز هم می‌آید. بدون تاریخ، تو بخش «کارهای بدون تاریخ» می‌ماند.
- **پشتیبان خودکار** بدون انتخاب پوشه تو حافظه‌ی داخلی برنامه ذخیره می‌شود و با حذف برنامه پاک می‌شود. برای امن‌تر بودن پوشه انتخاب کن.
- **پشتیبانی نسخه‌ها:** اندروید ۶ تا ۱۶. تو اندروید ۱۲ به بالا اعلان دقیق با مجوز «آلارم‌ها و یادآوری‌ها» انجام می‌شود (تو ۱۳ به بالا خودکار فعال است).

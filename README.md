# Planner — پروژه‌ی اندروید

برنامه‌ی مدیریت کارها و عادت‌ها برای اندروید.

- شناسه: `ir.dehgmahdi.planner`
- حداقل اندروید: ۶ (API 23)
- Target SDK: 36
- خروجی انتشار: APK امضاشده با keystore دائمی
- پروژه‌ی فعال: پوشه‌ی `planner-android/`

## ساختار مهم مخزن

- `.github/workflows/build-apk.yml` — Workflow فعال ساخت APK
- `planner-android/app/src/main/assets/planner.html` — رابط HTML داخل برنامه
- `planner-android/app/src/main/assets/overdue.js` — مدیریت کارهای عقب‌افتاده
- `planner-android/app/src/main/java/ir/dehgmahdi/planner/` — کد Kotlin فعال
- `planner.html` و `overdue.js` در ریشه — نسخه‌ی پیش‌نمایش مرورگر؛ باید با فایل‌های داخل assets همگام باشند
- `planner-update/` و فایل‌های قدیمی ریشه — نسخه‌های قدیمی/آرشیوی؛ برای ساخت APK فعال نیستند

برای توسعه‌ی اندروید، فقط فایل‌های داخل `planner-android/` و Workflow فعال را تغییر بده. فایل‌های پیش‌نمایش ریشه را هم هنگام تغییر HTML همگام کن.

## ساخت و دانلود APK

1. مخزن را در GitHub باز کن و وارد تب **Actions** شو.
2. Workflow **Build Planner APK** را انتخاب کن و **Run workflow** بزن.
3. پس از موفقیت، در همان اجرا بخش **Artifacts** را باز کن و فایل `Planner-APK` را دانلود کن.
4. APK داخل فایل ZIP با نامی مانند `Planner-1.0.N.apk` قرار دارد.

ساخت فقط APK تولید می‌کند، نه AAB. هر ساخت از GitHub Actions شماره‌ی نسخه‌ی بالاتری می‌گیرد.

## GitHub Actions Secrets

برای امضای release باید این چهار Secret در Settings → Secrets and variables → Actions موجود باشند:

- `KEYSTORE_BASE64` (یا نام سازگار قدیمی `ANDROID_KEYSTORE_BASE64`)
- `KEYSTORE_PASSWORD`
- `KEY_ALIAS`
- `KEY_PASSWORD`

فایل keystore را هرگز به مخزن اضافه نکن. از آن و رمز آن نسخه‌ی پشتیبان امن داشته باش؛ برای به‌روزرسانی برنامه‌ی نصب‌شده، گواهی امضا باید ثابت بماند.

## پشتیبان‌گیری

پشتیبان خودکار با WorkManager به‌صورت هفتگی زمان‌بندی می‌شود. در اولین اجرا یا پس از انتخاب پوشه‌ی پشتیبان، پشتیبان فوری هم در صف قرار می‌گیرد. اگر عملیات موقتاً شکست بخورد، Worker دوباره تلاش می‌کند. بدون انتخاب پوشه، نسخه‌ی خودکار در فضای داخلی برنامه ذخیره می‌شود و با حذف برنامه ممکن است از بین برود؛ انتخاب پوشه‌ی پایدار پیشنهاد می‌شود.

## چک‌لیست تست پس از ساخت

- نصب APK و بازشدن برنامه
- ثبت کار و عادت و بررسی وضعیت انجام‌شده/انجام‌نشده
- تکمیل یک کار عقب‌افتاده با یک بار لمس
- بررسی امتیاز پس از تکمیل کار و عادت
- دریافت اعلان واقعی در زمان تعیین‌شده
- ساخت پشتیبان، بازیابی آن و بررسی پشتیبان خودکار
- نصب APK نسخه‌ی جدید روی نسخه‌ی قبلی بدون حذف برنامه

ساخت موفق GitHub به‌تنهایی جای تست روی گوشی را نمی‌گیرد؛ اعلان، پشتیبان‌گیری و WebView باید روی دستگاه واقعی هم بررسی شوند.
